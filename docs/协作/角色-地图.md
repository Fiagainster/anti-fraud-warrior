# 角色手册 · 关卡 / 地图

## 两种工作流

### A. 程序化地图（推荐，当前主用）

地图由 `tools/gen_maps.py` 生成原生二进制 WAD（`game/maps/FZn.wad`）。
**生成器就是源码**，改布局 = 改 Python，产物不入库。

关键结构：

```python
# 扇区（地板高、顶高、地板扁平、顶扁平、亮度）
brief = m.sector(0, 128, floor, ceil, 190)
# 房间边界：一次调用画完，所有缺口在同一调用里给全
m.rect_walls(0, 0, 512, 512, brief, wall, gaps={"e": (192, 320)})
# 连接线（两扇区之间）
m.open_v(512, 192, 320, sec_east=c1, sec_west=brief)
# 门：lock 1=红 2=黄 3=蓝（生成器映射到 D1 常开门）
m.door(2432, 192, 2464, 320, LOCK_RED, sec_west=a2, sec_east=boss)
```

硬规则（都踩过坑）：

1. **房间边界只画一次**；重复调用会把先前留的门洞封死（空气墙）。
2. 缺口用世界坐标区间给全；凹室必须在主房间之外、共享边线，扇区不得重叠。
3. 竖直边绕向：y 递减（向南）时正面朝西——开关/门面要朝向玩家。
4. 贴图/扁平名必须在 IWAD 里存在（生成时校验），名称 NUL 填充。
5. 自定义 ednum < 32768；新增编号先登记到《资源与命名规范》。
6. 门面图形放 sidedef 的 **upper** 层；双面门扇线不加 ML_BLOCKING。

### B. 手工地图（当前不用，见下节说明）

复杂关卡可用 **Ultimate Doom Builder（UDB）**，但**不要拿它替换现有三章**——
连带成本见下一节。真要手工做，只新开一章（如 `FZ04.wad`），前三章原样不动。

**开工前必须设对的两项：**

- 地图格式选 **`Doom: UDMF`**（`gen_maps.py` 现在默认出 UDMF）。
  - 命名空间必须是 **`ZDoomTranslated`**：引擎会对它跑 xlat，行/扇区特殊值
    继续用 Doom 编号。换成 `zdoom` 命名空间就要把每个 special 手翻成
    Hexen 形式（门 31 → `Door_LockedRaise` 加锁参数、出口 52 →
    `Teleport_NewMap`，且走/用/射的触发方式要单独写 linedef flag），
    五个地方任何一个写错都是玩家走到门前才发现。
  - **散装 `.map` 会崩**：把 UDMF 地图当 `maps/xxx.map` 文本文件塞进 PK3，
    5.0.3 在启动阶段就 Access Violation（`0x8`）。同样的地图装进
    `xxx.wad`（marker + `TEXTMAP` + `ENDMAP`）就正常加载。`gen_maps.py`
    走的就是 WAD lump 这条路，别改成散装文件。
  - **不要 Boom 格式**：UZDoom 能加载，但它多一套 generalized linedef
    special 规则，和 `gen_maps.py` 的写法和校验对不上，最后项目里会有两套规则。
  - 格式是建图时定的，事后改很麻烦——新建时一次选对。
- 只用 Freedoom IWAD 里真实存在的贴图名，否则游戏里显示棋盘格。

**UDB 的操作方式和 Blender 完全不同，先接受这三条：**

1. **关卡里没有"物体"**，只有顶点、线、扇区。房间不是摆个盒子，是"画一圈首尾
   相接的线"，线自己围出来的那块地就是扇区。没有 extrude、没有网格、没有面。
2. **靠模式干活**。左侧竖排工具会随模式整套换掉（顶点 / 线 / 扇区 / 物件），
   进错模式就怎么点都没反应——这是新手最常见的手感问题来源。
3. **属性在对话框里，不在模型上**。双击线出线属性（门的 special 在这设），
   双击扇区出扇区属性（地板高度、天花板、贴图）。没有拖拽调整这回事。

**本项目的固定设置（错一个就白跑）：**

| 要做的东西 | 怎么设 |
|---|---|
| 门 | 两面线（front/back 都有），special `31/32/33`（DR，开后不自动关）或 `26/27/28`（自动关）；门面贴图放 **upper** 槽，不是 middle；这条线**绝不能勾 ML_BLOCKING** |
| 出口开关 | 墙线的 special `52`（W1 Exit Level） |
| 玩家起点 | Thing `1`，角度别留默认值 |
| 自定义物件（终端/证据/主谋） | 用 3920–3932 段的自定义 ednum，且必须 < 32768 |

**空地图直接试玩会进不去**：没放 Thing `1`（玩家起点）就没有出生点。

**保存与入库：**

- 存成 `assets_src/maps_src/FZ0x_<简述>.wad`，同目录写 `README.md` 说明挂载方式。
- 程序侧接进 `game/maps/`（或 PK3 流程）后，跑同样的验收：`gen_maps.py` 的贴图名
  校验、`fz_ctl check`、以及为新章补机器人路点。

## 为什么现在不换手工地图

换一张手工 WAD 不是"把 WAD 丢进去"就完事，有三样东西会跟着废：

| 连带项 | 现状 | 换图后 |
|---|---|---|
| 回归机器人路点 | `tools/testhooks/bot/zscript/fzbot.zs` 里 **27 个硬坐标**（`Wpx/Wpy` 全是字面数字） | 地图一动全废，四套回归（`tour`/`door`/`menu`/`full`）全红 |
| 贴图名校验 | `gen_maps.py` 生成期对照 IWAD 校验每个名字 | 手工图没有这道闸门，棋盘格只能靠眼睛发现 |
| 物件摆放 | 每章 35 个 thing 由程序算好坐标 | 35 个 thing 手工摆一遍，位置错一个就卡流程 |

回归全红意味着后续所有改动都没有安全网。所以顺序是：

1. **现在要差异 → 改 `gen_maps.py` 参数**（房间尺寸、门位、绕行动线都是一行数），
   一两天能出三套不一样的布局。
2. **将来要质感 → 单开一章** `FZ04.wad` 手工搓，前三章留着当回归基准。

## 新增一章的步骤

1. `tools/gen_maps.py` 的 `CHAPTERS` 增加一条：`name`、`palette`（墙/地板/顶）、`enemies1/2`、`boss_adds`、`gate_a/gate_b`。
   - 复用现有布局即可先跑通；新布局再改 `build_chapter()`。
2. `game/mapinfo/MAPINFO`：加 `map FZ04 "第四章：…" { Next=… Sky1=… Music=… }`，
   上一章 `Next` 指向它；更新 `episode`（如需章节菜单）。
3. `game/zscript/fz_gates.zs`：新增门 ID（如 41/42）与文案；`GateCorrect/GateStage/...` 同步。
4. `game/zscript/fz_hud.zs`：`ObjectiveText()` 增加新章节分支。
5. 字体：跑 `python tools\gen_font.py`（自动收集新文案字符）。
6. 测试钩子 `tools/testhooks/bot/zscript/fzbot.zs`：为新章加路线路点（布局相同可复用，改 mapname 判断即可）。
7. 验收：`fz_ctl check` → `build` → 新章场景（可先 `+map FZ04` 手动跑）→ `tour` 不回归。

## 关卡设计清单（发布前）

- 出生点 128 单位内无遮挡；主路径宽度 ≥ 96（门洞 ≥ 64）。
- 每个抉择终端前有 ≥ 128×128 的停留空间（弹菜单时玩家会被暂停）。
- 证据点可达且不被敌人堵死；Boss 房有回旋空间。
- 出口前有清晰视觉引导（开关墙/亮度对比）。
- **出口只有一个**，且主谋还活着时按不动（`fz_gates.zs` 的 `WorldLinePreActivated`
  拦所有 `Exit_Normal`/`Exit_Secret` 线）。设计时别留第二条能绕过 Boss 的出口，
  闸门拦的是"按出口"这个动作，拦不住"走到没放闸门的传送线"。
- 亮度不低于 150 的主路径，避免"看不清路"。

## 验收命令

```powershell
python tools\gen_maps.py      # 生成 + IWAD 名校验
python tools\build.py         # 打包
python tools\fz_ctl.py static # 静态逻辑 + 几何审计（改完地图第一件事）
python tools\audit_maps.py FZ02   # 只审一张图，逐项打印
python tools\fz_ctl.py tour   # 第一章回归（新章先手动或加场景）
```

`audit_maps.py` 每项对应一种玩家能看见的症状，三章都必须 0 条：
扇区边界不闭合（`[A]`）= 黑洞/能看穿，同侧叠面（`[B]`）= 闪面，
两面条高度缝缺贴图（`[C]`）= 一条透视带，物件落点/半径（`[D]`/`[D2]`）= 卡墙，
单面墙绕向（`[G]`）= 本该是阴影的地方变成黑洞而且能透视。

**单面墙右手规则**：单面墙所在的扇区必须在 `v1→v2` 的右手边。绕反了引擎就把法线
朝向室外，站在室内看到的是墙背面，于是纯黑 + 可透视。两个矩形房间共用一堵墙时，
两边各画一条方向相反的 coincident 单面线，别画一条双面线。

觉得审计"报错了"时先自证它有效：故意反转一条墙，`[G]` 必须报出来；
不报就是检查本身坏了，别据此删警告。
