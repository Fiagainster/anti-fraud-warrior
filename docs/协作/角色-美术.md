## 当前第一优先：三个道具图标

现在三个关键物件都在借用 Freedoom 的原版拾取物贴图，玩家看到的是护甲 / 背包 / 蓝钥匙——和"数据终端 / 证据箱 / 主谋证据"完全对不上。这三个是流程上必经的东西，收益最高。

| 画什么 | 现在借用的 | 画布 | 建议内容 |
|---|---|---|---|
| 数据终端（抉择点） | `ARM1 A`（护甲） | 48×48 | 立式终端 / 全息屏，带自发光边缘 |
| 证据箱 | `BPAK A`（背包） | 32×32 | 证物袋、卷宗袋、贴着封条的箱子 |
| 主谋证据 | `BKEY A`（蓝钥匙） | 32×32 | 账本 / U 盘 / 假公章，要一眼看出"这是铁证" |

### 画完还要接线，否则游戏里看不到

1. 文件放 `game/sprites/`，文件名 = **4 位 sprite 名 + 帧字母 + 朝向数字**，例如 `FZTRA0.png` 对应代码里的 `FZTR A`。名字只能 8 个字符、大写字母数字，小写/下划线/连字符都不认。
2. 改 `game/zscript/fz_defs.zs` 里对应的 `Spawn:` 那一行，例如：
   ```zscript
   Spawn:
       ARM1 A -1 Bright;   // 改成你的： FZTR A -1 Bright;
       Stop;
   ```
3. 贴图和碰撞体是分开的。图比原来的大或小，要跟着调同类的 `Default { Height / Radius }`，否则会浮空或陷进地板（拾取物带 `+FLOORCLIP`，按底部对齐）。
4. 终端是 `RenderStyle "Translucent" Alpha 0.85`，手画的图透过去会显得发灰。想要实色就改 `Alpha 1.0`。
5. **跑一次锚点脚本**：`python tools\fix_offsets.py apply`。PNG 的锚点只存在 PNG 内部的 `grAb` 块里，不写这一块，引擎会按 (0,0) 兜底——那不是"居中落地"，而是"图片左边缘对齐原点"，怪物会往右偏半个身位、往上顶一整张图的高度（看起来就是埋在地板里只露半个身子）。`check` 的期望输出是 `0 need offset`。
6. 打完包用 `python tools\fz_ctl.py gate` 进游戏看一眼，别只信文件放对了。想细看站位就跑 `python tools\fz_ctl.py show`，它会让怪原地不动、等开场简报（约 10 秒）自己过期后拍四张。

## 敌人 8 方向 sprite（第二阶段）

目标：替换 Freedoom 的敌人占位素材。

| 敌人 | 参考原型 | 章节 | 造型方向 |
|---|---|---|---|
| 刷单托儿 | Zombieman | 第一章杂兵 | 廉价西装/手机/工牌，谄媚表情 |
| 群主"闪电哥" | Baron of Hell | 第一章 Boss | 大金链、直播补光灯、夸张手势 |
| 黑市商人"暗影" | Imp/ShotgunGuy | 第二章 | 连帽卫衣、发光键盘、背包 |
| 影子会长 | Cacodemon 等 | 第三章 Boss | 假警服/面具（**不得使用真实警徽样式**） |

### 交付规格

- 8 个朝向（0=正面朝向玩家，顺时针每 45°），行走 4 帧 + 攻击 2 帧 + 死亡 4 帧（先做行走/待机即可）
- 画布：**64×64**（Boss 可 128×128），脚底对齐画布底部中心
- 背景透明（RGBA），不要抗锯齿到灰边；像素风请整数缩放
- 命名：`enemy_<角色>_dir<0-7>_walk<0-3>.png`（这是**源文件**命名，进游戏前还要映射成 Doom 的 8 字符 lump 名）
- 同时交付 `.blend` 源文件 + 一张 8 方向拼图预览

这一批成本比道具高得多：不只是画，还要替换生成器里的 ednum 映射、调碰撞体、重跑全套回归。等三个道具图标落地之后再动。

### 渲染管线

1. 在 Blender 中搭好角色，材质用简单色块也 OK（像素风靠渲染尺寸与描边）。
2. 相机正交、固定仰角 30°、围绕 Z 轴每 45° 渲染一张。
3. 参考脚本：`tools/blender/emblem_render.py`（无头渲染、输出 PNG、透明背景）。
4. 输出到 `assets_src/blender/out/<角色>/`，再由程序映射成 Doom sprite lumps。

## 场景贴图（收益很大）

- 目标：把 Freedoom 的科幻墙换成"诈骗园区/机房/直播间/审讯室"主题。
- 规格：64×64 或 128×128 无缝平铺；扁平（地/顶）为 64×64。
- 命名遵守《资源与命名规范》的 8 字符大写规则（如 `FZWALL1`）。
- 先在 `assets_src/textures/` 出源文件，再导入 `game/graphics/` 并登记到生成器调色板。
- 改完贴图必须重跑 `python tools\gen_maps.py`——它会拿 IWAD 校验每个名字，名字不存在直接失败（这是唯一挡得住"棋盘格"的闸门）。

## UI 图

- HUD 面板：320×48（参考 `game/graphics/FZPANEL.png`）
- 标题画：640×480（`TITLEPIC`）
- 结算/卷宗：640×400（`FZBKGRD1-3`）
- 主菜单补丁：`M_NGAME/M_OPTION/M_QUITG` 等，PNG 覆盖引擎英文图。

## 会被脚本覆盖的文件（重要）

`tools/gen_*.py` 直接写 `game/graphics/` 下的同名文件，**手画完再跑一次就没了**：

| 脚本 | 会覆盖 |
|---|---|
| `gen_panel.py` | `FZPANEL.png`、`FZBKPT.png` |
| `gen_titlepic.py` | `TITLEPIC.png` |
| `gen_menu_patches.py` | `M_*.png` |
| `gen_intermission.py` | `FZBKGRD*.png` |

手画这四类图时，要么改生成器让它跳过已存在的文件，要么把这几个脚本从日常重跑清单里划掉。`build.py` 只在文件**缺失**时才调 `gen_font.py` / `gen_maps.py`，不会覆盖已生成产物。

## 验收

1. 文件进入 `assets_src/`（源文件）与 `game/`（成品）且命名正确；
2. `python tools\build.py` 之后打出的 PK3 里能看到你的文件（`sprites/`、`sounds/`、`graphics/` 都会被打包）；
3. `python tools\fz_ctl.py tour` 不回归；
4. 游戏内截图（8 方向至少 4 张）贴到 PR；
5. Boss/敌人尺寸与碰撞体一致（碰撞体由程序按 sprite 尺寸调 `Radius/Height`）。

## 禁止事项

- 不使用真实警徽、真实机关标识、真实品牌 logo；
- 不直接描摹/拼接其他商业游戏素材；
- AI 生成素材必须登记模型、提示词与日期，避免版权争议。
