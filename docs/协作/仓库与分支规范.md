# 仓库与分支规范

## 分支模型

| 分支 | 用途 | 规则 |
|---|---|---|
| `main` | 可发布状态 | 只接受 PR；PR 必须过 `fz_ctl check`（改内容时再加 `tour`） |
| `feat/<域>-<简述>` | 新功能 | 例：`feat/art-enemy-sprites`、`feat/map-ch2-arena` |
| `fix/<域>-<简述>` | 修 bug | 例：`fix/door-red-key` |
| `content/<章>` | 剧情/地图批量内容 | 例：`content/ch4-loan-scam` |

域前缀统一用：`art` `map` `code` `story` `audio` `build` `docs`。

## 提交信息

```
<域>: <一句话做了什么>

可选：为什么、影响范围、验证方式
```

例：
- `map: 修复审判门 special 33 与门面 upper 纹理`
- `art: 新增刷单托儿 8 方向 sprite`
- `story: 第四章"虚假贷款"抉择文案`

一个提交只做一件事；二进制素材单独提交，避免和代码混在一起。

## PR 检查清单（复制到 PR 描述）

- [ ] 关联 Issue
- [ ] `python tools\doctor.py` 通过
- [ ] `python tools\fz_ctl.py check` 通过（脚本/地图/MAPINFO 改动必做）
- [ ] `python tools\fz_ctl.py static` 通过（196 项静态 + 几何审计三章各 0 条）
- [ ] 内容改动：`python tools\fz_ctl.py tour` 通过，并在 PR 里贴截图
- [ ] 动过 Boss/出口：`python tools\fz_ctl.py bosslock <章名>` 通过（Boss 活着时出口必须被拦）
- [ ] 新素材：命名/路径符合《资源与命名规范》，来源与授权写进 `assets_src/CREDITS.md`
- [ ] 没有把 `vendor/`、`build/`、`dist/`、`source/` 提交进库

## 评审规则

- 代码/脚本：至少 1 人 Review；涉及门/证据/结局的改动需测试同学确认。
- 美术：至少 1 名美术 + 1 名程序确认（尺寸/透明通道/方向数/命名）。
- 文案：至少 1 人校对 + 宣传口径审校（见《素材授权与AI合规》）。

## 定义完成（DoD）

1. 功能可在游戏内实测通过；
2. 自动化回归通过（check + 对应场景）；
3. 文档/命名同步更新；
4. 交付物在 `make_dist` 后能独立运行。
