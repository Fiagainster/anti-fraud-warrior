# 开发日志 · 2026-11-21

一句话：地图从二进制 WAD 换成 UDMF 文本，同时推翻了 11-20 记下的
"UDMF 会崩"这条结论——崩的是散装 `.map`，不是 UDMF。

## 起因：能不能让 AI 直接接管地图编辑

问的是 Ultimate Doom Builder（UDB）源码已下到 `UltimateDoomBuilder/`，
能不能让 AI 接管地图制作。读源码的结论是：**不能，而且不该往这个方向使劲**。

三条硬约束（都在源码里查过）：

| 约束 | 证据 | 后果 |
|---|---|---|
| 没有批处理 / 无头模式 | `Core/General/General.cs` `ParseCommandLineArgs` 只有 9 个开关（`-MAP` `-CFG` `-RESOURCE` `-PORTABLE` `-NOSETTINGS` `-DELAYWINDOW` `-SCRIPTCONFIG` `-STRICTPATCHES` `-DEBUGRENDERDEVICE`） | 全是"打开 GUI 时用什么配置"，没有"跑完就退"的入口 |
| UDBScript 改不了文件系统 | `Source/Plugins/UDBScript`（Jint + Esprima，19 个 wrapper，`MapWrapper` 36 个方法），但 `UDBWrapper` 只有 `log`/`showMessage`/`exit`/`die`/`setProgress`/`setStatus`，**全 API 无 open/save/export** | JS 只能改当前已打开的那张图，存盘还得人按 Ctrl+S |
| 改无头等于重写 | `Core/Builder.csproj` 是 `OutputType=WinExe` + `.NET Framework 4.7.2`，564 个源文件里 165 个 `using System.Windows.Forms` | 不是加开关的事 |

唯一能跑的闭环是"写 .js → 丢进 `UDBScript/Scripts/` → 绑热键到脚本槽（源码
里有 `udbscriptexecuteslot1..30`）→ winbot 发键 → 再发 Ctrl+S"。技术上通，
但依赖窗口焦点和弹窗，脆得很，而且 `gen_maps.py` 已经能无头产图，没必要。

**所以改道的不是"谁按鼠标"，而是"地图用什么表示"**：二进制 WAD 对 AI 不友好
（算 lump 偏移、8 字符短名、`struct.pack` 下标），UDMF 是纯文本，能读能 diff
能直接改。

## 关键选择：`ZDoomTranslated` 而不是 `zdoom`

UDMF 的 `zdoom` 命名空间用引擎内部（Hexen）行特殊值。这个项目只用了 5 个
特殊值——门 31/32/33、出口 52、开关 11——但要手翻成 Hexen 形式，每一个都是
坑：门要变成 `Door_LockedRaise` 加锁参数，出口变成 `Teleport_NewMap`，而且
"走/用/射"的触发方式从 special 编号里挪到了独立的 linedef flag 上。五个地方
任何一个写错，都要等玩家走到门前才发现。

`ZDoomTranslated` 让引擎自己跑 xlat，**特殊值继续用 Doom 编号**，语义和二进制
图完全一致，ZScript 一行不用改。`gen_maps.py` 里的 5 个数字原样保留。

代价：UDB 不认这个命名空间（源码里零出现），将来要人在编辑器里改图得换成
`zdoom` 并手工翻译那 5 个值。这条记在 `docs/协作/角色-地图.md`。

## 顺手证伪："UDMF 会崩 5.0.3"

11-20 的日志写着"格式必须 vanilla（UDMF 会崩）"，`tools/udmf_bisect.py` 就是
当时留下的排查脚本。今天先用它复现，三次启动全部崩在
`Checking cmd-line parameters...` 之后、地图加载之前，而且 `zdoom` 和
`ZDoomTranslated` **死法完全一样**——说明根本不是命名空间的问题。

最后一组对照把话说死了（同一个房间、同一份文本，只改打包方式）：

| 打包方式 | 结果 |
|---|---|
| PK3 → `maps/L01.map`（散装文本） | **CRASH**，Access Violation 读 `0x8` |
| PK3 → `maps/L02.wad`（marker + `TEXTMAP` + `ENDMAP`） | 正常加载，`G_ParseMapInfo` / `LoadActors` / `R_Init` / `M_Init` / `P_Init` 全到 |

所以老结论该改成：**PK3 里放散装 `.map` 会崩**，UDMF 装进 WAD lump 没问题。
README 第 8 条坑位本来就写着"地图必须打成 PWAD 磁盘文件"，今天算是补上了它
的准确边界。`tools/udmf_bisect.py` 已删——它生成的地图是必然崩的那种。

## 改了什么

`tools/gen_maps.py`
- 类 `VanillaMap` → `MapBuilder`（它现在两种格式都能出，名字不该再骗人）；
- 新增 `udmf_text()` / `udmf_bytes()`，输出 `namespace = "ZDoomTranslated"`；
- WAD 组装抽成 `wad_from(lumps)`，`wad_bytes()` 和 `udmf_bytes()` 共用；
- `--format udmf|vanilla`，**默认 udmf**。

`tools/test_game_logic.py`
- `parse_wad()` 现在认 `TEXTMAP`，把 UDMF 解成和二进制一样的 dict 结构，
  下游所有几何断言（可达性、门、出口、贴图名）一行没改；
- 新增 `test_format_equivalence()`：同一章同时序列化两种格式，逐字段比对
  顶点/边/扇区、线条顶点对与标志、特殊值与 tag、物件坐标朝向编号选项位。
