## 夜间：第二、三章逻辑修复（20:30–21:30）

起因是玩家实测反馈：**第一章没问题，第二章走到头要钥匙却没有，第三章无法验证**。
读代码 + 只读日志后确认是三个独立 bug 叠在一起，全部修完并补了自动化。

**1. 二三章根本没有抉择终端（根因）**

`gen_maps.py` 用 `3920 + (gate_a - 11)` 算终端 ednum。第一章 gate_a=11 → 3920 正确；
第二章 21 → **3930**、12 → **3931**——而这两个编号是"证据箱"和"主谋证据"；
第三章 31 → **3940**、32 → **3941** 未注册，引擎按 Unknown type 静默丢弃。

于是第二章地图里一个终端都没有（只有 3 个证据箱 + 1 个主谋证据），玩家走到审判门
自然"要钥匙但没有"——不是钥匙丢了，是**压根没有抉择、凑不出证据链**。
第三章同理，整章没有任何可交互对象。

修法：改成显式映射表 `GATE_EDNUM = {11:3920, 12:3921, 21:3922, 22:3923, 31:3924, 32:3925}`，
并在生成期加 `check_things()` 断言：每章 2 个终端各一次、gate id 必须在表内、
P1 出生点 1 个、简报 1 个、证据箱 3 个、Baron 1 个、禁止出现 `4`（Player 4 Start）
/`8`（Backpack）这类会撞引擎语义的编号。

顺带修掉 `enemies1/enemies2` 里的 `4` 与 `8`：`4` 是 Player 4 出生点，`8` 是背包
（贴图还和证据箱一样），它们从来没生成过怪物。现在统一用 `ZOMBIE/SHOTGUNNER/IMP/
DEMON/BARON/CACO` 常量，并断言怪物列表只能取这几个值。

**2. 换关背包继承 → 下一章状态是脏的**

Doom 换关靠 `ObtainInventory` 把整包东西交给下一关（武器/钥匙就是这么传的），
我们的 `FZStage1/2`、`FZEvidence`、`RedCard` 也跟着过去了。后果：
- 第二章一开始就带着 `FZStage1/2`，终端认为"这道题答过了"直接关闭 → 没有证据；
- 审判门要么天然开着（红卡跟着过来了），要么永久锁死（证据数卡在 3、红卡却没了，
  证据箱还拒绝再给第 4 件）。

修法：`FZPlayEvents.WorldLoaded` 里 `ClearChapterState()` 把章节级令牌全部清零。
`WorldLoaded` 在读档时**不触发**（`src/events.cpp`），所以存档安全；实测日志
`FZDBG: chapter reset FZ02 ev=0 red=0 st1=0 st2=0 st3=0`。

**3. 横幅只显示 3 次就永久失效**

`FZMsgItemBase.Tick()` 里用 `Amount = 0` 收尾，但 `Amount = 0` 不销毁物件，
`FindInventory` 仍能找到"幽灵"——三个消息槽被占满后，之后所有横幅（简报/识破/
正确/主谋证据）再也不出现。改成 `Destroy()`。

**4. 站在终端里会被反复喂菜单，扣血扣死**

答错后玩家还在终端触发区内，`FZGateCool` 一次就被吃掉，下一 tic 又弹菜单，
25 点一次反复扣到死、然后重开本章（日志里出现 3 轮菜单 + 3 次开门）。
给终端加**每终端冷却** `mCool`（140 tic ≈ 4 秒，够读完横幅），两个分支都进冷却、
答对时同时 `done = true`。修复后菜单次数 9 → 4。

**5. 新增静态测试 `tools/test_game_logic.py`（158 项）**

不启动引擎，纯 Python 解析三张 WAD（THINGS/LINEDEFS/SIDEDEFS/SECTORS）、
MAPINFO 的 `doomednums` 与 `Next` 链、ZScript 源码，交叉校验：
换关链、终端编号、门数据与 `GateCorrect/MsgText/GateStage` 一致性、
证据链阈值、审判门（两片门扇共享一门扇区、upper 纹理、special 33）、
可达性（防空气墙）、纹理名存在于 IWAD。**158/158 通过**。

**6. 引擎内场景扩到 5 个**

| 场景 | 结果 | 说明 |
|---|---|---|
| `static` | **161/161** | 不启动引擎 |
| `chapter FZ02` | **13/13** | 门前 ev=3 red=1、门开、进 Boss 房、出口进第三章 |
| `chapter FZ03` | **13/13** | 最后一章，出口触发结束序列 |
| `lock` | **16/16** | 全答错但捡满证据 → ev=3 仍 red=0、门不开 |

door.`**：机器人卡住可能只是被怪挡住，而这句话是门确实锁着的第一手证据。

**设计修正：抉择拿到了否决权（原"已知设计问题"已解决）**

原来的规则是"凑满 3 件证据就发红卡"，而三个证据箱自己就能凑满 3 件——于是
"两题全答错、只捡箱子"照样能开审判门，反诈题白答。玩家也提了同样的疑问。

讨论过两种改法：
- A. 答对才算证据、证据箱只补到上限 2：会剩一个永远用不上的箱子（墙上摆三个，
  第三个白给），而且两题全错时证据上限 2 < 3，必须靠重答补救。
- B（采用）。红卡 = 证据 3 件 **且** 本章两道抉择都答对。证据箱负责凑数，
  答题决定能不能结案；三个箱子正好都用上，`ev=3` 语义不变。

"答错会不会卡关"的答案是**不会**：`FZGateTerminal` 只在答对（或已持有该题
Stage 令牌）时置 `done`，答错只进 4 秒冷却。走开再靠近，菜单重新弹出，代价是
掉警惕值 + 伏击。为了让玩家不误会成 bug，加了 905 横幅："证据链已齐，但还有
抉择没答对——回到闪烁终端重新作答"，并把三条提示文案改成明确写"答错可以
走开再回来重答，不会被锁死"。

验证：`lock` 改成"全答错但捡满三个箱子"，断言 `ev=3` 且 `red=0`、门不开（16/16）；
新增 `retry` 场景把补救路径跑出来——第一题故意答错 → 机器人走回终端 → 第二次
弹菜单答对 → `red=1` → 进 Boss 房（9/9）。静态测试加了 3 条守这条线的断言
（红卡必须校验 Stage、`done` 只在答对时置位、冷却机制存在），161/161。
