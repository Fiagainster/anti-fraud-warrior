## 一句话结论

怪物"埋在地里只露半个身子"和"武器错位"是同一个病：PNG 精灵没写锚点，
引擎按 (0,0) 兜底。补上 `grAb` 之后两类精灵都归位，公式和标定值都落在
`tools/fix_offsets.py` 里，不再靠试。

同一天把 P0 做掉了：三个流程必经物件（终端 / 证据箱 / 主谋证据）不再借
Freedoom 的护甲 / 背包 / 蓝钥匙，占位图由 `tools/gen_props.py` 程序化生成，
接线也改完了。下一步是音效，见 `docs/下一步.md`。

## 病根

UZDoom 读 PNG 精灵时只认 PNG 内部的 `grAb`（grab）块：

```
src/common/textures/formats/pngtexture.cpp:158   tex->SetOffsets(ihotx, ihoty);
```

没有这个块，`LeftOffset/TopOffset` 保持 0。而 0 的语义不是"居中"，是
"图片左边缘对齐角色原点、图片顶边对齐角色头顶"——所以每张图往右偏半个
身位、往上顶一整张图的高度。64 高的怪 = 埋到胸口，正是玩家看到的样子。

传统 patch 格式的精灵把这对值写在文件头 8 个字节里（w,h,left,top），
所以老美术资源从来不会有这个问题；换成 PNG 之后这个信息就丢了。

墙和地板不受影响：它们是平铺的 tile，只有尺寸和重复，没有锚点。这也解释
了"为什么只换一张图就会错位"——错位跟图长什么样无关，只跟有没有写锚点有关。

## 修法：照抄原版的真值，别自己发明

原版值直接从 `vendor/freedoom-0.13.0/freedoom1.wad` 的 patch 头读出来：

| lump | 尺寸 | left | top | 规律 |
|---|---|---|---|---|
| POSSA1 | 41x57 | 22 | 53 | left=w/2, top=h-4 |
| TROOA1 | 48x60 | 23 | 56 | 同上 |
| SARGA1 | 38x59 | 17 | 55 | 同上 |
| BOSSA1 | 49x69 | 24 | 69 | top=h |
| MEDIA0 | 29x20 | 14 | 20 | top=h |
| STIMA0 | 19x10 | 10 | 10 | top=h |
| PISGA0 | 82x92 | -125 | -97 | 武器，负数、量级一百多 |

于是规则三条：

- 人形怪 `(w/2, h-4)`——脚底故意埋 4px，站着才不像飘；
- 地上道具 `(w/2, h)`——图片底边正好落在原点；
- 弹道/烟/爆炸 `(w/2, h/2)`——没有脚，居中即可。

之前那版写的是 `(w/2, 0)`，横向修对了、纵向把整张图挂在原点下方，
所以"不再左右歪"但"照样埋地里"。这次是纵向也修了。

## 武器是另一套坐标系

第一人称武器（psprite）不是贴在世界原点上，是相对屏幕中线画的，所以
原版给的是负数。水平方向的公式从源码能推干净：

```
gametexture.cpp:SetSpriteRect()      mSpriteRect.left = -LeftOffset
hw_weapon.cpp:GetWeaponRect()        tx = sx - (160 - r.left)
                                     x1 = tx * scalex + vw / 2
=>  x1 = (LeftOffset - 160) * scalex + 160
```

想让 w 宽的枪在 320 宽虚拟屏里居中，反解出 `LeftOffset = w/2 - 160`。
56 宽的警示枪就是 -132。

垂直方向算不准：`y1 = vh/2 - (100 - r.top) * scale`，其中 `vh` 是扣掉
状态栏之后的视口高，引擎没暴露。所以 `WEAPON_BOTTOM_ROW = 148` 是拿截图
反推的标定值——先让枪飘在屏幕中间量一次顶边，再落到 HUD 上量一次，线性
解方程。换 HUD 高度就得重新标定，这一点在代码注释里写死了。

试过但走不通的路，记下来免得下次再踩：给 `TEXTURES` 写 `sprite PISGA0
{ Offset ... }` 覆盖（对 psprite 无效，枪被推到左上角）、把武器画进
320x200 透明画布再归零（武器完全不渲染）。

不算失败，只是少几个角度。

## P0：三个流程必经物件换成自研图

角色全换之后，最后一眼穿帮的就是这三个：终端显示成绿护甲、证据箱显示成背包、
主谋证据显示成蓝钥匙（`fz_defs.zs` 里 `ARM1 A` / `BPAK A` / `BKEY A`）。

占位图不靠手画，用 `tools/gen_props.py` 程序化出——这样能重跑、能对着代码调轮廓，
你之后按同名覆盖母版就行。

| 精灵名 | 画布 | 轮廓 | 关键设计 |
|---|---|---|---|
| `FZGT` | 48×56 | 竖长 | 暗钢机柜 + 亮青数据行 + 顶上红灯（有题待答）+ 天线 |
| `FZEV` | 32×24 | 矮宽 | 米白箱体 + **偏右的**红封条 + 顶部标签 |
| `FZPF` | 26×26 | 方小 | 一叠账本 + 一枚切角红章 |

两个坑：

- **证据箱的封条不能居中**。正中十字会读成"礼物盒丝带"，往右偏两像素就像贴歪的
  封条胶带。
- **红章不切角就是红方块**。26px 下画不了字，靠"四角各切一像素 + 一道小十字"
  做成圆形感。

## 锚点分类别用 `startswith("FZ")`

`FZGT` / `FZEV` / `FZPF` 也是 `FZ` 开头，但它们是摆在地上的道具，得按 `top=h`，
不是人形怪的 `top=h-4`。原来的 `name.startswith("FZ")` 会在这一步静默埋掉 4px。
改成显式的 `MONSTERS` 六元素集合，多写一行，少踩一个坑。

## `gen_props.py` 三档，`apply` 不覆盖手画的图

生成器最容易被骂的地方是"跑一次把美术覆盖了"。所以：

| 档位 | 行为 |
|---|---|
| `check` | 只报告母版有没有、尺寸多少，不写文件 |
| `apply` | 母版**不存在**才画占位；存在就只同步进 `game/sprites/` 并补 `grAb` |
| `force` | 连已有母版一起重画成占位（明确要覆盖时才用） |

## 夜间追加：启动器、持枪贴图与难度

### 1. run.bat 报 "Files missing"

包没缺资源。`run.bat` 只按"当前目录"找 `uzdoom.exe` / `freedoom1.wad` /
`fanzha-demo.pk3`，在压缩包预览窗口里双击时，Windows 只把 `.bat` 单独解到
`%TEMP%`，三个检查必然失败；另一种情况是杀软隔离了无签名的 exe。

启动脚本已改为：路径全部锚定 `%~dp0`、逐个报出缺失文件的完整路径、识别
"在 zip 临时目录里运行"并提示先解压、exe 缺失时提示查杀软隔离区。README 里
也补了「打不开？」一节。

### 2. 手持武器贴图回归 IWAD

自制枪械贴图的问题是**透视**：AI 只会画枪的侧视图，贴着屏幕底边就成了"枪口朝左"，
准星自然别扭。试过用原版当参考图做 i2i、试过把侧视图旋转+纵向压缩，结果都不如原版，
不再把半成品放进包。

现在 `game/sprites/` 里删掉了 `PISG*` / `SHTG*`（9 个文件），引擎直接读 Freedoom
原版持枪帧；**其它一律不动**：弹药、开火、换弹、拾取全是老逻辑。后续自制贴图以原版
帧的构图/透视当骨架重画。设计稿保留在 `docs/角色美术设计.md` §4.2，并标注了当前状态。

地上的枪没有跟着换：拾取物仍是自制版。用 `FZPistol`/`FZShotgun` 的 A 帧横置、缩到
拾取尺寸，存成 `PISTA0.png`（30×20）和 `SHOTA0.png`（58×14），覆盖 IWAD 的同名
lump，所以躺在走廊里的枪还能一眼认出橙色警示条和白色封条。手持与地面用的是两套图，
互不影响。

### 3. 答错惩罚召唤原版怪物

`fz_gates.zs` 的 `GateAmb()` 返回 `'DoomImp'` 这类 IWAD 类名，而 `Ambush()` 用的是
`Spawn(..., NO_REPLACE)`，替换表被绕过，于是出现原版 Freedoom 怪物。改成直接返回
`FZShill` / `FZRunner` / `FZScalper` / `FZFakeCop`。
